## 4. Enforce the provider cleanup contract

- [x] 4.1 Make local storage deletion remove the exact final file and any staging or partial file for the same operation, while treating only confirmed absence as success; verify failure-after-write and repeated-deletion cases with filesystem tests.
- [x] 4.2 Make S3-compatible deletion remove the base object, manifest, exact numbered chunks and incomplete multipart uploads even when the manifest was never published, without deleting prefix-neighbor objects; verify all cases against the repository MinIO test container, including repeated deletion and an injected mid-upload failure.
- [x] 4.3 Make Azure deletion cover committed objects and uncommitted blocks for the exact operation. Guard the block-discarding step on blob existence rather than on a non-empty committed block list, because a blob written with one Put Blob has no committed blocks and committing an empty list over it would truncate real content. The step assumes Azure answers Get Block List for a blob that was never committed, which Azurite does; if Azure answers 404 instead, the step becomes a silent no-op that nothing in this repository can detect. Azurite cannot verify this end to end, because its `DeleteBlob` succeeds on a blob holding only uncommitted blocks and drops them, while Azure returns 404 and keeps charging for the blocks for a week; verify the block-discarding step directly instead, that a committed blob is not emptied by it and that `DeleteFile` still removes a committed blob and tolerates an absent one.
- [x] 4.4 Make Google Drive treat a missing `databasus_backups` folder as a confirmed absence rather than an error, since cleanup would otherwise retry that obligation for as long as the storage exists, and leave rclone unchanged because it already resolves one exact object and returns any lookup error that is not a confirmed absence. `deleteByName` already lists every file with the exact name in the backups folder and deletes each, which covers a duplicate left by an interrupted attempt. Verify rclone against a local remote for the exact-path, similarly-prefixed, sidecar, absent and repeated cases. Google Drive has no test double or container in this repository and needs live OAuth, so it stays covered by inspection.
- [x] 4.5 Tighten FTP, SFTP and NAS deletion so only an explicit not-found result is acknowledged as success and connectivity, permission and ambiguous failures are retried. Each one drops its stat probe and classifies the removal reply instead, because the probe was where any error became a silent success. Verify with provider tests that a stored file is gone after deletion and that an absent one still succeeds, and unit test the FTP reply classifier. Cover the refusal branch for SFTP and NAS by deleting a non-empty directory, in each provider's own package, where the test can reach the connection helper that creates it; `SaveFile` cannot, because it does not create parent directories. Absence is covered by the existing provider table, except on NAS, where the configured path is a directory that never exists and so also covers a removal whose parent is missing. FTP has no equivalent, because 550 is its answer to both a missing file and a refused one, so its classifier is unit tested instead.
